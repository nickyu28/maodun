## 角色
只玩、查、报告，**不改任何游戏代码、不改别人的文件、不碰分支 industry**。报告写 `docs/playtest-<日期>.md`，只改这一个文件，普通推送到 main（`git pull --rebase origin main` 再 `git push origin HEAD:main`），docs 的推送不触发 CI。

## 怎么玩（这台机器的限制）
- 连不上线上页面和 PeerJS：本机 `python3 -m http.server`，Playwright + Chromium 玩，peerjs 请求用 `tests/peerjs-stub.js` 换掉，只能单人。
- 不是键鼠真操作：脚本直接调游戏自己的函数（`indGather`、`indCraft`、`fiLightCook`、`wdChop`、`indAction` 等），所以等待时间、手感要在报告里说明"没测手感"。
- 网址带 `?notut=1` 会关怪物自动刷新、点火免费、**也会关教程**；测怪要手动开 `IND_MB_AUTO`，硬核测点火要手动把 `IND_FIRE_FREE` 关掉，测教程不要带 `?notut=1`。
- 猫盾工业对所有人开放了（11-14，按钮标"测试版"）；调试函数（`indBagAdd`、`indMoonEnter`、`indMoonPick`、`indMoonLeave`）要 `?hcdebug=1`。
- 角色会死：脚本每隔几秒游戏时间检查一次渴了去喝、饿了吃；死过不算游戏 bug，原因要写（脚本没喝水、没穿对衣服等）。

## 每份报告的格式
①做对了的 ②没覆盖的 ③行为跟任务文档对不上的（怎么复现、屏幕写了什么字）④玩家会以为是 bug 的体验问题（作者 11-08 两次把"背包满了""物品没样子"当成 bug，这类要单列）；末尾写用了多少步、大概多久。写"做过"之前先确认那件东西已经在 main 上（`git show --stat` 或 grep），提交说明写了任务名不等于代码做了。
